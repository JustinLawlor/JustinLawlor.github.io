Overview

The problem

The raw table had a date stored with a time, missing property addresses, whole addresses crammed into one column, inconsistent Yes/No values and duplicate sales. Each step below fixes one of those problems, explains why, and shows the code.

Step 1

Standardize the sale date

Why: SaleDate was stored as a date and time, which makes grouping by day awkward. What the code does: adds a new date-only column and fills it from SaleDate.

ALTER TABLE NashvilleHousing
ADD SaleDateConverted Date;

UPDATE NashvilleHousing
SET SaleDateConverted = CONVERT(Date, SaleDate);
Step 2

Fill in missing property addresses

Why: some rows had no PropertyAddress, but another row with the same ParcelID did. What the code does: joins the table to itself on ParcelID (different UniqueID) and copies the address across wherever it is missing.

UPDATE a
SET PropertyAddress = ISNULL(a.PropertyAddress, b.PropertyAddress)
FROM PortfolioProject1.dbo.NashvilleHousing a
JOIN PortfolioProject1.dbo.NashvilleHousing b
  ON a.ParcelID = b.ParcelID
  AND a.[UniqueID] <> b.[UniqueID]
WHERE a.PropertyAddress IS NULL;
Step 3

Split the property address into columns

Why: street and city were in one field, separated by a comma. What the code does: finds the comma with CHARINDEX and uses SUBSTRING to cut the text on either side into two new columns.

ALTER TABLE NashvilleHousing ADD PropertySplitAddress NVARCHAR(255);
UPDATE NashvilleHousing
SET PropertySplitAddress = SUBSTRING(PropertyAddress, 1, CHARINDEX(',', PropertyAddress) - 1);

ALTER TABLE NashvilleHousing ADD PropertySplitCity NVARCHAR(255);
UPDATE NashvilleHousing
SET PropertySplitCity = LTRIM(SUBSTRING(PropertyAddress, CHARINDEX(',', PropertyAddress) + 1, LEN(PropertyAddress)));

2026 review: the original UPDATE for the street started the substring at the comma instead of at position 1, so the new column held the wrong text. The code above is the corrected version, and LTRIM removes the space left after the comma.

Step 4

Split the owner address with PARSENAME

Why: the owner address had street, city and state in one field. What the code does: PARSENAME splits text on periods, so the commas are swapped for periods first. It counts from the right, which is why the street is part 3 and the state is part 1.

ALTER TABLE NashvilleHousing ADD OwnerSplitAddress NVARCHAR(255);
UPDATE NashvilleHousing SET OwnerSplitAddress = PARSENAME(REPLACE(OwnerAddress, ',', '.'), 3);

ALTER TABLE NashvilleHousing ADD OwnerSplitCity NVARCHAR(255);
UPDATE NashvilleHousing SET OwnerSplitCity = PARSENAME(REPLACE(OwnerAddress, ',', '.'), 2);

ALTER TABLE NashvilleHousing ADD OwnerSplitState NVARCHAR(255);
UPDATE NashvilleHousing SET OwnerSplitState = PARSENAME(REPLACE(OwnerAddress, ',', '.'), 1);
Step 5

Make Yes/No values consistent

Why: SoldAsVacant mixed Y, N, Yes and No. A quick GROUP BY count showed the mix first. What the code does: a CASE statement rewrites each value.

UPDATE NashvilleHousing
SET SoldAsVacant = CASE WHEN SoldAsVacant = 'Y' THEN 'Yes'
                        WHEN SoldAsVacant = 'N' THEN 'No'
                        ELSE SoldAsVacant
                   END;
Step 6

Remove duplicate sales

Why: the same sale appeared more than once with different IDs. What the code does: ROW_NUMBER numbers rows that share the same parcel, address, price, date and legal reference. Any row numbered 2 or higher is a duplicate and gets deleted through the CTE.

WITH RowNumCTE AS (
  SELECT *,
         ROW_NUMBER() OVER (
           PARTITION BY ParcelID, PropertyAddress, SalePrice, SaleDate, LegalReference
           ORDER BY UniqueID
         ) AS row_num
  FROM PortfolioProject1.dbo.NashvilleHousing
)
DELETE FROM RowNumCTE
WHERE row_num > 1;

2026 review: the original script ended this DELETE with ORDER BY PropertyAddress, which SQL Server doesn't allow, so it has been removed.

Step 7

Drop the columns that were replaced

Why: once the split and converted columns existed, the originals were redundant. What the code does: drops them.

ALTER TABLE PortfolioProject1.dbo.NashvilleHousing
DROP COLUMN OwnerAddress, TaxDistrict, PropertyAddress, SaleDate;
Results

What I learned

The table now has a clean date column, no missing property addresses, separate street, city and state columns, consistent Yes/No values and no duplicate sales.

What I learned

  • How to change a table with ALTER TABLE and fill new columns with UPDATE.
  • How to join a table to itself to fill gaps using matching rows.
  • How to split one text field into several with SUBSTRING, CHARINDEX and PARSENAME.
  • How to find and delete duplicates with ROW_NUMBER inside a CTE.
  • Looking back: check the new column after every update. A quick look would have caught the address-split bug.
